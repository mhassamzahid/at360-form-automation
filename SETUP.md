# Meta Lead Form → Webhook Setup Guide

This guide connects a Meta (Facebook/Instagram) **Instant Form** to this backend, so every submission
reaches `/webhooks/meta`. From there we send notifications and emails.

**How it works**

```
Someone submits the form
  → Meta sends a webhook to  https://<your-url>/webhooks/meta   (contains only IDs)
  → Backend checks the form ID against META_FORM_IDS
  → Backend fetches the answers from Meta using the Page access token
  → Backend runs handle_new_lead() in app/notify.py  (log + leads.jsonl now, emails/notifications next)
```

Meta renames menus often. If a label differs slightly from this guide, look for the closest match.

---

## Values you'll collect

| `.env` key | What it is | Where it comes from |
|---|---|---|
| `META_APP_ID` | Developer app ID | Step 1 |
| `META_APP_SECRET` | Developer app secret (used to verify webhooks are really from Meta) | Step 1 |
| `META_VERIFY_TOKEN` | Any random string you make up | Step 5 |
| `META_PAGE_ID` | The Facebook Page that owns the form | Step 2 |
| `META_FORM_IDS` | The form(s) to act on, comma-separated. Empty = all forms | Step 2 |
| `META_SYSTEM_USER_TOKEN` | Long-lived token for the business | Step 3 |
| `META_PAGE_ACCESS_TOKEN` | Page token used to read leads | Step 7 (generated by script) |

## 1. Developer app basics

**Where:** [developers.facebook.com/apps](https://developers.facebook.com/apps) → `at360-form-automation`

1. **App settings → Basic**
   - Copy **App ID** and **App secret** into `.env`.
   - Fill these in (you can't publish the app without them):
     - **App domains:** `aheadtech360.com`
     - **Privacy policy URL:** `https://www.aheadtech360.com/privacy`
     - **User data deletion:** a URL with deletion instructions, e.g. `https://www.aheadtech360.com/data-deletion`
     - **App icon:** a square logo, 1024×1024
     - **Category:** *Business and pages* (or closest)
   - Click **Save changes**.
2. **Use cases → Customize** (on the lead ads use case). Make sure these permissions are added:
   - `leads_retrieval`
   - `pages_manage_metadata`
   - `pages_read_engagement`
   - `pages_show_list`
   - `business_management`

   These don't need App Review because you're only using Pages your own business owns.
3. Make sure the app belongs to your Business portfolio: **App settings → Advanced → Business account**
   (or the business shown on the dashboard).

---

## 2. Find the Page ID and Form ID

**Where:** [business.facebook.com/settings](https://business.facebook.com/settings) (**Business settings**, not Ad account settings)

- **Page ID:** **Accounts → Pages** → click your Page → copy the ID shown under its name.
  → `META_PAGE_ID`
- **Form ID:** Meta Business Suite → **All tools → Instant forms** (the Forms library) → click the form
  (e.g. *4 Nov Main Form*) → copy the **Form ID** from the details panel.
  → `META_FORM_IDS` (separate multiple forms with commas)

---

## 3. Create a system user and token

A system user is a non-human account for your business, so its token doesn't break when a person leaves or changes their password.

**Where:** Business settings → **Users → System users**

1. Click **Add**.
   - **Name:** e.g. `at360-form-automation`
   - **Role:** **Employee** is enough. Admin works too but isn't needed.
2. Select the system user → **Assign assets**:
   - **Apps** → `at360-form-automation` → turn on **Manage app** (full control).
   - **Pages** → your Page → turn on **full control** (or at minimum: content, messages, **leads**,
     community activity, ads).
   - Click **Save changes**.
3. Click **Generate new token**:
   - **App:** `at360-form-automation`
   - **Token expiration:** **Never**
   - **Permissions:** tick the five permissions from step 1.2.
   - Click **Generate token**.
4. **Copy the token immediately**, because Meta shows it only once → `META_SYSTEM_USER_TOKEN`.

> If a permission is missing from the list, add it to the app's use case first (step 1.2), then generate again.

---

## 4. Allow the app to read leads

**Where:** Business settings → **Integrations → Leads access**

1. Select your Page.
2. On the **CRMs** tab, make sure `at360-form-automation` is listed and allowed. If it isn't, click **Assign CRMs** and add it.
3. On the **People** tab, make sure the system user has access.

> Skip this step and the webhook still arrives, but fetching the answers fails with a permissions error.

---

## 5. Run the backend and expose it

```powershell
cd D:\at360-form-automation
.venv\Scripts\activate
pip install -r requirements.txt        # first time only
uvicorn main:app --reload --port 8001
```

Port **8000** is taken by another project on this machine, so use **8001**.

In a second terminal:

```powershell
ngrok http 8001
```

Check it's working by opening `https://<your-ngrok-url>/health`. You should see `"verify_token_set": true`.

> `--reload` restarts on code changes only. **Restart uvicorn after editing `.env`.**

---

## 6. Configure the webhook

**Where:** [developers.facebook.com/apps/2062314334481545/webhooks/](https://developers.facebook.com/apps/2062314334481545/webhooks/)

1. Object dropdown → **Page** (not User / Application / WhatsApp).
2. **Subscribe to this object**:
   - **Callback URL:** `https://<your-ngrok-url>/webhooks/meta`
   - **Verify token:** the exact value of `META_VERIFY_TOKEN` in `.env`
   - Click **Verify and save**.
3. In the field list, set **`leadgen`** to **Subscribed**. Leave everything else (including `leadgen_update`) off.
4. Click **Test** next to `leadgen`. The uvicorn terminal should print `Webhook received: {...}`.
   A *"Could not fetch lead"* error after that is expected, because the test lead is fake.

---

## 7. Connect the Page to the app

This is the step people forget. Without it, **real submissions never trigger the webhook**.

With `META_PAGE_ID` and `META_SYSTEM_USER_TOKEN` in `.env`:

```powershell
python -m scripts.setup_page
```

The script:
1. Gets the Page access token
2. Subscribes the Page to the app for `leadgen`
3. Prints `META_PAGE_ACCESS_TOKEN=...`

Paste that line into `.env` and **restart uvicorn**.

---

## 8. Publish the app

**Where:** developer app → **Publish** (left sidebar)

While the app is **unpublished**, Meta only sends the dashboard **Test** webhooks. Real leads, including
leads from admins and testers, are **not delivered** until the app is published.

---

## 9. Test end to end

1. Open the [Lead Ads Testing Tool](https://developers.facebook.com/tools/lead-ads-testing).
2. Select your Page and form → **Create lead**.
3. In the uvicorn terminal you should see:
   ```
   Webhook received: {...}
   NEW LEAD 1234567890: {'full_name': '...', 'email': '...', ...}
   ```
4. The lead is also saved to `leads.jsonl`.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| *"Callback URL or verify token couldn't be validated"* | Server not running, ngrok pointing at the wrong port, or token mismatch. Open `/health` through the ngrok URL. Check ngrok's inspector at `http://localhost:4040`. |
| ngrok shows **404** for `/webhooks/meta` | ngrok is forwarding to a different app. Make sure ngrok and uvicorn use the same port (8001). |
| **401 Invalid signature** in logs | `META_APP_SECRET` is wrong or belongs to a different app. |
| Test button works, real leads never arrive | Step 7 not done (Page not subscribed), or app not published (step 8). |
| *"Could not fetch lead … permission"* | Leads access (step 4), or the token is missing `leads_retrieval`. |
| *"Ignoring lead from form …"* | That form's ID isn't in `META_FORM_IDS`. |
| Changed `.env` but nothing changed | Restart uvicorn. |
| ngrok URL changed | Update the Callback URL in step 6 and click **Verify and save** again. |

## Project files

| File | Purpose |
|---|---|
| `main.py` | Entry point for `uvicorn main:app` |
| `app/main.py` | Webhook endpoints: GET (verification) and POST (lead events) |
| `app/meta.py` | Signature check and fetching the lead's answers from Meta |
| `app/notify.py` | `handle_new_lead()`, where emails and notifications go |
